# Шпаргалка по командам Git

## Настройка и создание репозитория

| Команда | Назначение и место выполнения |
|---|---|
| `git --version` | Версия Git; любая папка. |
| `git config --global user.name "Имя Фамилия"` | Имя автора коммитов по умолчанию; это не вход в GitHub. Без `--global` настройка действует только в этом репозитории. |
| `git config --global user.email "your-email@example.com"` | Email автора коммитов. Используйте подтверждённый адрес GitHub или noreply из настроек. |
| `git init -b main` | Создаёт локальный репозиторий и ветку `main` в текущей папке; удалённый репозиторий не создаёт. |
| `git clone <URL>` | Клонирует репозиторий в новую папку и обычно добавляет `origin`. Для работы с fork клонируйте свой fork. |

## Состояние, файлы и коммиты

| Команда | Назначение и место выполнения |
|---|---|
| `git status` | Показывает ветку, изменения, новые файлы и состояние незавершённой операции. Выполнять в репозитории. |
| `git status --short` | Краткий статус; `??` означает новый неотслеживаемый файл. |
| `git remote -v` | Показывает имена и URL удалённых репозиториев; проверьте перед обменом изменениями. |
| `git remote add origin <URL>` | Добавляет адрес remote с именем `origin`, но не передаёт файлы или коммиты. После `clone` обычно уже есть. |
| `git remote add upstream <URL-оригинала>` | Добавляет адрес оригинала автора в локальном клоне fork. |
| `git remote set-url origin <URL>` | Меняет URL существующего `origin`; сначала посмотрите `git remote -v`. |
| `git add README.md` | Подготавливает файл к коммиту и начинает отслеживать его, если он новый. |
| `git add .` | Подготавливает изменения в текущей папке и подпапках, включая новые файлы и удаления, с учётом `.gitignore`. Сначала проверьте `git status`. |
| `git check-ignore -v scratch.txt` | Показывает правило, игнорирующее файл. |
| `git diff` | Показывает неподготовленные правки отслеживаемых файлов; новые файлы не отображаются. |
| `git diff --staged` или `git diff --cached` | Показывает подготовленные изменения. Проверьте их перед коммитом. До первого коммита показывает всё подготовленное содержимое. |
| `git diff HEAD` | Показывает изменения отслеживаемых файлов относительно текущего коммита. |
| `git restore --staged README.md` | Убирает файл из индекса, сохраняя правки в рабочем файле. |
| `git commit -m "Добавлена памятка"` | Создаёт локальный коммит из подготовленных изменений. Проверьте текущую ветку и `git diff --staged`. |
| `git log --oneline -5` | Показывает пять последних коммитов; если открылся просмотрщик, нажмите `q`. |
| `git show HEAD` | Показывает сведения и изменения текущего коммита; можно указать хеш вместо `HEAD`. |
| `git log --oneline --graph --all` | Показывает локально известную историю веток; сначала сделайте `fetch`, чтобы получить свежие данные с remote. |

## Ветки и слияния

| Команда | Назначение и место выполнения |
|---|---|
| `git branch` | Показывает локальные ветки; текущая отмечена `*`. |
| `git branch --show-current` | Показывает текущую ветку; проверяйте перед `commit`, `merge`, `pull` и `cherry-pick`. |
| `git switch -c improve-topic` | Создаёт ветку от текущего положения и переключается в неё. |
| `git switch main` | Переключается на локальную `main`; сначала проверьте `git status` и сохраните нужные правки. |
| `git merge improve-topic` | Включает `improve-topic` в текущую ветку. Для слияния в `main` сначала переключитесь на `main`; начните с чистым деревом. Результат локальный. |
| `git merge --abort` | Отменяет незавершённое слияние, но не отменяет уже созданный merge-коммит. |

## Fork, upstream и отправка изменений

В клоне fork `origin` должен вести в ваш fork, а `upstream` — в оригинальный проект. Проверьте через `git remote -v`.

| Команда | Назначение и место выполнения |
|---|---|
| `git fetch origin` | Получает коммиты и обновляет сведения об удалённых ветках; не объединяет их с текущей веткой. |
| `git fetch upstream` | Получает историю оригинала; сам не меняет рабочие файлы. |
| `git branch -r` | Показывает известные удалённые ветки, например `origin/main` и `upstream/main`. |
| `git merge upstream/main` | Включает полученные изменения оригинала в текущую ветку. В учебном сценарии: в `improve-topic`, после `git fetch upstream` и при чистом дереве. Возможен конфликт. |
| `git push -u origin main` | Публикует локальную `main` в `origin` и настраивает связь с `origin/main`. Требуется заранее созданный на GitHub репозиторий и настроенный `origin`. |
| `git push -u origin improve-topic` | Публикует рабочую ветку в `origin` и настраивает отслеживание удалённой ветки. В fork проверьте URL `origin`. |
| `git push` | Отправляет коммиты текущей ветки в связанную удалённую ветку; незакоммиченные правки не отправляет. |
| `git pull --ff-only origin main` | Получает `main` из `origin` и обновляет текущую ветку только fast-forward. Сначала переключитесь на `main` и проверьте чистый статус. При расхождении история не сольётся автоматически. |
| `git merge --ff-only upstream/main` | Обновляет текущую ветку до `upstream/main`, только если возможен fast-forward. Для синхронизации fork: переключитесь на `main`, выполните `git fetch upstream`, затем при необходимости `git push origin main`. |

Fork и pull request создаются в браузере GitHub.

## Cherry-pick и конфликты

| Команда | Назначение и место выполнения |
|---|---|
| `git cherry-pick <HASH>` | Применяет коммит к текущей ветке, обычно создавая новый коммит; исходный остаётся на месте. Переключитесь в ветку-получатель и проверьте чистый статус. |
| `git cherry-pick --continue` | Продолжает cherry-pick после исправления конфликта и `git add` исправленных файлов. |
| `git cherry-pick --abort` | Отменяет незавершённый cherry-pick. Для merge используйте `git merge --abort`. |

### Разрешение конфликта

Исправьте содержимое вручную, удалите маркеры конфликта и проверьте результат. Затем выполните `git add <файл>`. Для обычного merge завершите операцию командой `git commit -m "Согласована тема встречи"`; для cherry-pick — `git cherry-pick --continue`. Чтобы отказаться от незавершённой операции, используйте соответствующий `--abort`.
